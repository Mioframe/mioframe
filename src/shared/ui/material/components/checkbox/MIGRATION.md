## Migrated consumers

All six consumers import the canonical `MDCheckbox` from `@shared/ui/material` (or, for consumer 6, in place of a relative deep import of the legacy file) — independently re-confirmed by direct reading of each usage site during this pass:

- **`SettingsCheckboxListItem.vue`** (ARCHITECTURE.md migration plan step 1): `<MDCheckbox v-else presentation :checked="checked" :disabled="disabled" />`. `MDListItem role="checkbox" aria-checked @action` ownership is unchanged.
- **`DatabaseViewsSheet.vue`** (step 2): `MDCheckbox` is imported alongside `MDButton` from `@shared/ui/material`; `<MDCheckbox presentation :checked="viewId === effectiveViewId" />`. The row's own click-handling ownership (`DatabaseViewListEdit`) is unchanged.
- **`RelationValueFieldData.vue`** (step 3): `<MDCheckbox :checked="selectedValue.includes(itemId)" @update:checked="onUpdateSelectedValue(itemId)" />`. `onUpdateSelectedValue` ignores its event argument and always calls `props.onSelect(itemId)`, so this rename is behavior-preserving. **Recorded decision:** this consumer's pre-existing missing-accessible-name gap (no `aria-label` was ever supplied) is deliberately **not** fixed by this migration — it is carried forward unchanged, per ARCHITECTURE.md's "Migration plan" step 3 and the risk it records. It is left as an explicit follow-up for a future accessibility-focused change, not tracked further here.
- **`MDCheckboxField.vue`** (step 4, the largest change): internally composes the canonical `MDCheckbox` instead of rendering its own hand-rolled `<label>`/`<input>` DOM. Its own public prop surface is `{ disabled, label, indeterminate, autofocus }` — `error` and `readonly` are dropped because ARCHITECTURE.md's "Non-goals" confirms neither is selected on the canonical `MDCheckbox` and neither is used by any of the four current downstream consumers. The component:
  - translates its own `boolean | undefined` tri-state `modelValue` onto the canonical `checked`/`indeterminate` pair (`checked = modelValue === true`; `indeterminate = props.indeterminate && modelValue === undefined`);
  - owns its own tri-state activation cycle via the existing `toggleBoolean` helper (`toggleBoolean.ts`, unchanged) — a single real user activation fires `MDCheckbox`'s `update:checked`/`update:indeterminate` pair together, and `MDCheckboxField` uses `update:checked` only as the one-per-activation trigger, recomputing the true next tri-state value itself rather than writing back the renderer-derived binary values directly;
  - forwards its own `label` text as `aria-label` on the composed `MDCheckbox` — the confirmed-working accessible-name backstop required by ARCHITECTURE.md step 4, given `M3E-005` (native `<label for>` association does not produce an accessible name for `m3e-checkbox`);
  - forwards a generated `id` so the external `<label :for="id">` click-forwarding association continues to work;
  - preserves the pre-existing autofocus-on-mount behavior by calling `.focus()` on the composed `MDCheckbox`'s root element (via a template ref exposing `$el`) when `autofocus` is true and the field is not disabled.

  `id`/`aria-label` are forwarded through a single `v-bind="hostAttrs"` binding (with a documented `eslint-disable-next-line vue/no-restricted-v-bind` justification matching the established `MDListItemDomContractStory.vue` precedent), because `MDCheckbox`'s typed public props intentionally exclude its host-attribute allow-list. This migrates `DatabaseBooleanPropertyEditSection.vue`, `BooleanPropertySettingsSection.vue`, and both `BooleanValueField.vue` consumers automatically through `MDCheckboxField`'s own internal composition — independently re-confirmed by direct source inspection in this pass: none of those four files imports `MDCheckbox`/`shared/ui/Checkbox` beyond the expected `MDCheckboxField`/`toggleBoolean` exports (`EditableInlineValue.vue` likewise only imports `toggleBoolean`).

- **`BooleanValueInline.vue`** (step 5): the previous single-root `MDCheckbox` (legacy `readonly` + `tabIndex="-1"` + `aria-hidden="true"` + a bundled `tooltip` prop) is replaced by a root `<span class="boolean-value-inline">` wrapping `<MDCheckbox presentation :checked :indeterminate />` and an externally composed `<MDPlainTooltip :text="name" />` sibling (Checkbox itself owns no tooltip surface after migration, per ARCHITECTURE.md's "Non-goals"). `MDPlainTooltip`'s default `target` falls back to its own parent element (`useParentElement()`), so the new wrapping `<span>` is the effective hover target, preserving the same "hover the checkbox area to see the tooltip" behavior.
- **`MDListItemConsumerPatternsStory.vue`** (discovered consumer, not in ARCHITECTURE.md's named inventory): imports `MDCheckbox` from `@shared/ui/material`; both "Settings: Checkbox row" usages bind `presentation :checked="..."`. This is a Storybook-only fixture; the change was required purely to keep the file importable and buildable after legacy removal, not because it counts as confirmed product demand.

Naming-collision note: no file imports both the legacy and canonical `MDCheckbox` under the same local name at any point — all six consumers were migrated together in one pass, so ARCHITECTURE.md's "transitional window" naming-collision risk never materialized. Independently re-confirmed: the legacy `MDCheckbox.vue` no longer exists, so no collision surface remains today.
