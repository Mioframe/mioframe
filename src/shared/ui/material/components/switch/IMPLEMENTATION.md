## Public API implemented

- Canonical export: `MDSwitch` from `@shared/ui/material`.
- Props: `selected` (`boolean`, default `false`, controlled via `update:selected`); `disabled` (`boolean`, default `false`); `presentation` (`boolean`, default `false`, Mioframe composition extension).
- Slots: none.
- Emit: `update:selected(value: boolean)`, fired only from a real renderer-driven native `change`, never while `presentation` is true.
- Root: one semantic `m3e-switch`; no wrapper element, no exposed imperative API.
- Host boundary: `inheritAttrs: false`; only merged `class`/`style`, `id`, `title`, `data-*`, `aria-label`, and `aria-labelledby` reach the host. Adapter-owned `checked`, `disabled`, and (when `presentation`) `tabindex`/`aria-hidden` retain precedence over any forwarded value.

## Tokens and renderer mappings

No `components/switch/tokens.css` file and no `docs/token-api.md` change, matching ARCHITECTURE.md's zero-token selection: the installed renderer consumes Mioframe's public `--md-sys-color-*`/`--md-sys-shape-*` foundation tokens directly for its default appearance.

Renderer mappings implemented exactly as selected by ARCHITECTURE.md's "Renderer mapping and gaps" table:

- `selected` → renderer `checked` Boolean property (typed via `Pick<M3eSwitchElement, 'checked' | 'disabled'>` in `m3eSwitch.d.ts`), with `update:selected` derived from a native `change` event.
- `disabled` → renderer `disabled` Boolean property.
- `presentation` → wrapper-owned `tabindex="-1"`, `aria-hidden="true"`, and host CSS `pointer-events: none` (via the `md-switch_presentation` modifier class), fully wrapper-owned and never forwarded to the renderer as a property/attribute.
- No `icons`, `name`, `value`, or drag-to-toggle surface is exposed or wired, matching the deferred/missing/not-applicable rows.
- Accessible name via `aria-label`/`aria-labelledby`: confirmed `direct` by real-browser proof, matching ARCHITECTURE.md revision `2026-08-11T02:00:00.000Z`. Accessible name via native `<label>`/`for` association: the wrapper-owned `id` forwarding itself is `direct` and proven, but real-browser proof shows the installed renderer/browser combination does not surface an accessible name from that association; ARCHITECTURE.md now classifies this row `divergent` (`M3E-004`, recorded in `docs/m3e-defects.md`) rather than `direct`. No implementation change follows from the reclassification: `MDSwitch.stories.ts` and `tests/e2e/storybook/md-switch-family.spec.ts` already used only `aria-label`/`aria-labelledby` fixtures for every accessible-name scenario (confirmed by direct inspection during this revalidation), never native `<label>` wrapping or `for`/`id` association, so the implemented surface already matched the now-corrected classification.
