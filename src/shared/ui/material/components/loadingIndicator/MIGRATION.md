## Migrated consumers

- No consumer source required editing. `MDButton.vue`'s existing composition (`class`, `aria-hidden="true"`, declared `label`/`size` props) fits entirely inside the corrected allow-list; the scoped-CSS `data-v-<hash>` attribute is a separate matter — Vue applies it to the component's root element unconditionally during rendering, independent of `inheritAttrs`/`$attrs`/the `forwardedAttrs` allow-list filter, so it was never subject to that filter and reaches the host regardless. This was independently re-verified in this migration pass by reading `MDButton.vue` and confirming both the explicit forwarding rules in `MDLoadingIndicator.vue` (`forwardedAttrs` handling `id`/`title`/`aria-hidden`/`aria-describedby`/`data-*`, plus separate `class`/`style` merge bindings) and the Host-attribute boundary tests in `MDLoadingIndicator.test.ts`.
- No Storybook fixture required editing; `AttributeBoundary` intentionally exercises rejected inputs as proof and is not a consumer requiring a supported destination.
- No unrelated legacy/generic loading UI (for example `SettingsSections`'s own `data-testid="loading-indicator"` checkbox-loading stub) was touched.

## Preserved scenarios and failure paths

- Standalone accessible purpose labeling and progressbar semantics (`label` remains the sole `aria-label` source; unaffected by this correction).
- Default, explicit, clamped, and non-finite overall sizing (unaffected; these are declared props, never `$attrs`).
- Material-primary standalone color, contextual public `--md-comp-loading-indicator-active-indicator-color` override via `style`, and legacy-surface isolation (all still reach the host through the allow-list).
- Button decorative child semantics: `aria-hidden="true"` suppression, 24 px geometry, `currentColor` token handoff via the merged `style`/scoped `class`, `aria-busy`, leading-icon replacement/restoration, native interaction, and consumer-owned disabling — all confirmed to still reach the renderer host through the new explicit allow-list rather than the previous unrestricted fallthrough.
- Provider/browser wait failure, cancellation, and retry behavior remains feature-owned and unchanged; those flows are not Loading Indicator consumers and were not affected by the boundary correction.
- Newly preserved (by design, not by consumer breakage): raw renderer `variant`/`contained`/`role`, value ARIA (`aria-valuenow`/`aria-valuemin`/`aria-valuemax`), `tabindex`, and arbitrary listeners no longer reach `m3e-loading-indicator` from any caller — no current consumer depended on this leaked access.
