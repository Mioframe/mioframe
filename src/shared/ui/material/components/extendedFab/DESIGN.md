## Identity and purpose

- Use the extended FAB for the single most common or important action on a screen.
- Use it instead of a plain FAB when label text is needed to make the action understandable, or to add further visual emphasis to the primary action.
- Three current variants: **small**, **medium**, **large** (M3 Expressive, added May 2025). All three align with the corresponding FAB sizes for easier transitions between FAB and extended FAB.
- A **baseline** extended FAB (56dp, single size, no small/medium/large distinction) also exists but is **no longer recommended** as of the M3 Expressive update; official guidance is to replace it with the small extended FAB.
- A **surface** color style also exists but is **no longer recommended**; it remains available but should be avoided in new designs.
- **M3 Expressive update (May 2025)**: added the small/medium/large size variants with updated (larger) type styles; deprecated the baseline extended FAB and the surface color style in favor of the small extended FAB and non-surface color styles.
- **Differences from Material 2**: new color mappings compatible with dynamic color; the extended FAB is now the same height as the plain FAB (in M2 it had a different, pill-shaped height/elevation model); boxier shape with a smaller corner radius; simpler elevation model shared with the FAB.
- **Adjacent-component distinctions**:
  - The plain FAB (`floating-action-button`) is icon-only and has no label; the extended FAB adds a label alongside the (optional) icon and is used when label text is required for the action to be understood. The FAB and extended FAB can transform into each other responsively (see Responsive layout below).
  - `fab-menu` is a distinct official family (FAB that opens a menu of further FABs) and is out of scope of this document.
  - Only one extended FAB should appear per screen; when several actions of similar prominence are needed, use filled buttons instead of multiple extended FABs.

## Anatomy and content

Anatomy (from both the overview/specs image captions and the guidelines page):

1. **Container** — a rounded rectangle that hugs its content; grows and shrinks with label text length (dynamic width); fixed height per size variant.
2. **Label text** — required content role. Should clearly describe the action in 1–2 words; avoid text that wraps or gets truncated (localization may lengthen the label and widen the container).
3. **Icon (optional)** — should intuitively represent the action. An icon-label relationship must be clear; per official guidance an extended FAB "can't have an icon without a text label," i.e. label text is mandatory while the icon is optional.

### Placement / screen margins

- Extended FABs should have **16dp margins** from the edge of the screen/container they float over.
- Compact/medium window sizes: place at the bottom of the screen, either center-aligned or aligned to the trailing edge.
- Expanded and larger window sizes: place at the bottom-right edge of the window (both LTR and RTL), or within an (expanded) navigation rail.
- Place the extended FAB above the rest of the UI (e.g. above app bars), not overlaid on toolbars, not in the upper half of a mobile screen, and not on cards or inside other containers.
- Avoid combining a floating toolbar with an extended FAB on the same screen (floating toolbars may be paired with a plain FAB, not an extended FAB).
- RTL: mirror icon/label placement — icon leads (left) in LTR, icon leads (right) in RTL.

### Elevation

Elevation is expressed per color-style token set and per interaction state (see catalogue): enabled container elevation is level3 (6dp); hovered is level4 (8dp); focused and pressed return to level3 (6dp). A separate "lowered" elevation ladder exists on some color styles (branded, primary, secondary, tertiary, surface — not on the tonal-container styles): lowered-enabled level1 (1dp), lowered-hover level2 (3dp), lowered-focus level1 (1dp), lowered-pressed level1 (1dp). Shadow color for all styles resolves to `md.sys.color.shadow`.

## States and behavior

Documented interaction states (from the specs "States" section and its state-image captions): **Enabled**, **Hovered** (elevation increases to level4/8dp), **Focused**, **Pressed**. No **Disabled** state and no **Dragged** state are documented for the extended FAB in the fetched official content (see Source conflicts and unknowns).

Per-state token behavior (see full catalogue): each non-deprecated color style defines, per state, a container elevation, a state-layer color/opacity (hover 0.08, focus 0.10, pressed 0.10), and (for hover/focus/pressed) label-text and icon color overrides. Focus additionally has a dedicated focus indicator: 3dp thickness, 2dp outer offset, `md.sys.color.secondary` color — consistent across every color style.

### Behavior / motion (qualitative — no extended-fab-scoped motion duration/easing tokens exist in the fetched token catalogue)

- **Appearing**: the extended FAB's surface expands into place using an "enter and exit" transition pattern (linked to the shared `/m3/pages/motion-transitions/transition-patterns` foundation, not a component-scoped token).
- **Expanding**: the extended FAB can expand and adapt into any shape (including a surface that is part of the app structure, or one that spans the whole screen) using a "container transform" transition pattern.
- **Transforming**: the extended FAB can transform into a plain FAB to temporarily take up less space.
- **Scrolling**: the extended FAB collapses into a FAB on scroll-down and expands back to an extended FAB on scroll-up. When a FAB switches to an extended FAB: the shape changes, the icon moves to the leading (left, LTR) position, and the label text fades in.

## Usage guidance

- Use on screens with long, scrolling views that need persistent access to one action (e.g. a checkout screen), or wherever label text helps the action be understood, or to add emphasis to the primary action.
- The icon-label relationship must be clear; an extended FAB can be effective where an icon alone would be ambiguous.
- Only one extended FAB per screen — multiple extended FABs compete for attention and disrupt visual hierarchy. If more high-emphasis actions are needed, add buttons elsewhere on the page.
- Do not use an extended FAB as one option within a set of actions (e.g. alongside a "back" button); use an appropriately styled button (e.g. a filled button) for that level of emphasis instead.
- **Choosing a size**: three variants (small/medium/large) let the designer add the right amount of emphasis. In compact windows with one prominent action, a large extended FAB can be appropriate; in larger window sizes, use a medium or large extended FAB.
- **Responsive layout**: the FAB and extended FAB can transform into each other depending on available space/layout — e.g. a collapsed navigation rail uses a FAB, and an expanded rail can transform it into an extended FAB.

## Accessibility

- **Use cases**: assistive-technology users must be able to navigate to and activate the extended FAB.
- **Interaction & style / placement for AT users**: on large web screens, consider placing the primary action (extended FAB) in the upper-left region (e.g. an expanded navigation rail) to make it easier for screen-reader users to reach. In smaller windows, the best placement is the lower-right corner. Do not place the extended FAB over another actionable element.
- **Initial focus**: the extended FAB should be prioritized in the overall focus order — on mobile, focus order may go app bar → navigation bar → (skip other content) → extended FAB. The visible label and icon are treated as **one** focusable element. A tooltip is not required/needed because the visible label already provides the accessible description.
- **Keyboard navigation**:

  | Keys           | Action                          |
  | -------------- | ------------------------------- |
  | Tab            | Moves focus to the extended FAB |
  | Space or Enter | Activates the extended FAB      |

- **Labeling elements**: use a consistent icon + text label combination with one distinct purpose (e.g. a Compose icon with a "Compose" label). The accessible name **must include the same first word as the visible label** — e.g. if the visible label is "Create," the accessible name might be "Create a new invite."

## Source conflicts and unknowns

- **Baseline padding attribute vs. asymmetric leading/trailing tokens**: the specs page's raw "Baseline extended FAB" attribute table states a single `Padding: 16dp`, while the baseline token set (`md.comp.extended-fab`) defines asymmetric `leading-space: 16dp` and `trailing-space: 20dp` (with `icon-label-space: 12dp`). Both are verbatim official values; the source does not reconcile the single "16dp padding" summary line against the asymmetric token pair. Recorded as-is; not resolved by inference.
- **Minimum container width documented only for baseline**: the baseline attribute table states "Container width: Dynamic, 80dp min." No equivalent minimum-width value is documented anywhere in the fetched official content (overview/guidelines/accessibility/specs/token catalogue) for the small, medium, or large size variants — width for those sizes is only describable as "dynamic, hugs content" plus the leading/icon-label/trailing space tokens. This is a genuine gap in the current official snapshot, not an inferred value.
- **Color-token-set `container.height`/`container.shape` vs. size-token-set `container.height`/`container.shape`**: five of the eight color sets (branded, primary, secondary, tertiary, surface) each carry their own `container.height` (always `56dp`) and `container.shape` (always the 16dp/`corner.large` value) tokens, while the three tonal-container color sets (primary-container, secondary-container, tertiary-container) do not define `container.height`/`container.shape`/`icon.size`/focus-indicator/typography tokens at all. The specs page states tokens are "organized by size and color" as two axes, but the fetched catalogue does not show an explicit rule for which axis's geometry tokens take precedence when a medium/large size is combined with a branded/primary/secondary/tertiary/surface color style (whose own `container.height` token literally says `56dp`, i.e. the small/baseline value). Recorded as an open combination question in the source, not resolved by inference.
- **"Branded" color style has no matching narrative documentation**: the token catalogue defines a complete `md.comp.extended-fab.branded` token set (distinguishable by its 36dp icon size and `on-surface` label color), but the guidelines/overview/specs narrative text never names a "branded" extended FAB variant or explains when to use it, unlike the six styles pictured in the specs "Color roles" image caption. The token set is real and complete; its usage guidance is absent from the fetched official narrative pages.
- **`Extended FAB - Color - Surface` token display names read "Extended FAB (primary)"**: every display name in the `md.comp.extended-fab.surface.*` token set (e.g. `md.comp.extended-fab.surface.container.color` → "Extended FAB (primary) container color") uses "(primary)" instead of "(surface)" in its display name, while the exact token name and resolved value are unambiguous and surface-specific (container color resolves to `surface-container-high`, not the primary color). Preserved verbatim as an upstream display-name authoring artifact; the token name/value pairing (not the display-name string) is authoritative.
- **No documented Disabled or Dragged state**: the specs "States" section and its accompanying image captions document only Enabled, Hovered, Focused, and Pressed for the extended FAB. No Disabled state and no Dragged state token or narrative entry exists in the fetched official content for this component (present or absent — this is the complete documented state set, not an omission by this document).
- **Motion timing/easing values are not component-scoped tokens**: "Appearing," "Expanding," "Transforming," and "Scrolling" behavior is documented qualitatively and links to the shared `/m3/pages/motion-transitions/transition-patterns` foundation page (not fetched as part of this component-scoped design pass); no extended-fab-scoped duration/easing token exists in the 12 fetched token sets.
- Cache route entries for `guidelines`/`accessibility`/`specs`/`overview` report `coverageStatus: stale` per the cache's own 7-day TTL bookkeeping; this reflects cache-refresh scheduling, not a content gap (`routeCoverageSummary`: 0 failed, 0 unresolved for the accepted route set; `qualitySummary`: 0 suspicious/duplicate/short pages). Not treated as a blocker per the design-stage fallback rules.

## Related official contracts

- **Floating action button** (`floating-action-button`) — the plain, icon-only FAB. The extended FAB and FAB transform into each other responsively (space-constrained layouts, and on-scroll collapse/expand). Distinct official family/route; out of scope of this document.
- **FAB menu** (`fab-menu`) — a FAB that opens a menu of further FABs. Distinct official family/route; not covered here.
- **Buttons (filled button)** — official alternative when an extended-FAB-level action needs to appear as one option among several (guidelines explicitly say to use a filled button instead of an extended FAB for that case).
- **Navigation rail** — an expanded navigation rail is a documented placement location for the extended FAB (large-window layouts); a collapsed rail uses the plain FAB instead.
- **Floating toolbar** — documented as incompatible to pair with an extended FAB on the same screen (floating toolbars may be paired with a plain FAB only).
- **Delegated system/reference foundations** (via token aliases, not separately re-fetched as component pages): `md.sys.color.*` roles (primary/secondary/tertiary/surface and their container/on-_ pairs), `md.sys.elevation.level1–level4`, `md.sys.shape.corner.large` / `corner.large-increased` / `corner.extra-large`, `md.sys.state.hover|focus|pressed.state-layer-opacity`, `md.sys.state.focus-indicator._`, `md.sys.typescale.label-large`/`title-medium`/`title-large`/`headline-small`, and the underlying `md.ref.palette._`/`md.ref.typeface._` reference tokens.
- **Motion foundation** — `/m3/pages/motion-transitions/transition-patterns` ("enter and exit" and "container transform" patterns), referenced qualitatively by the guidelines page's Behavior section.
