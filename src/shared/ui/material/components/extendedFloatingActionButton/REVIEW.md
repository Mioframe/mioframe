# PR #212 review

## Blocker — the real-Tab focus proof remains reproducibly nondeterministic

- **Owner:** `MDExtendedFloatingActionButton.browser.spec.ts`
- **Problem:** the current correction waits for `tabIndex === 0` before the real `Tab`, but the coding-agent verification reproduced the same failure about 2 times in 7 isolated runs after this exact change. Instrumented diagnostics reported stable `tabIndex === 0` for both FABs before `Tab` in both passing and failing runs. Therefore the added readiness assertion does not establish the missing deterministic precondition and the original flaky blocker is not fixed. The proposed explanation that this is merely container input-dispatch jitter is not verified.
- **Evidence:** [current focus test](https://github.com/Mioframe/mioframe/blob/79c75efe559024367a94f1597144fabb2be78da3/src/shared/ui/material/components/extendedFloatingActionButton/MDExtendedFloatingActionButton.browser.spec.ts); [`@m3e/web` 2.7.4 Focusable lifecycle](https://github.com/matraic/m3e/blob/12e0ddcefeed35bacea317d417d73a0732d32d0d/packages/web/src/core/shared/mixins/Focusable.ts); [one exact-head behavior run](https://github.com/Mioframe/mioframe/actions/runs/32288734556/job/96184531326) passed 76 tests without a retry, but a single green run does not invalidate the supplied repeated local reproduction.
- **Basis:** [testing architecture](https://github.com/Mioframe/mioframe/blob/79c75efe559024367a94f1597144fabb2be78da3/docs/testing/architecture.md) requires the lowest faithful deterministic proof and requires flaky failures to remain visible rather than being weakened or hidden. Material browser proof must exercise the real public interaction contract.
- **Risk:** a known reproducible flaky proof can intermittently fail the required browser lane and there is no evidence yet that the failure is environmental rather than an incomplete test setup or lifecycle contract. `failOnFlakyTests` correctly makes this merge-blocking rather than ignorable noise.
- **Required final state:** identify the actual nondeterministic precondition or starting-focus state and make the real-Tab proof deterministic without sleeps, arbitrary delays, retries, programmatic focus of the FAB target, production behavior changes made only for the test, or weakening `failOnFlakyTests`. If the contract is only “the FAB is reachable by keyboard Tab” rather than “it is the first document tab stop”, prefer an explicit deterministic focus origin/test fixture over relying on browser initial focus state, provided the real `Tab` transition to the FAB remains the behavior being proven.
- **Verification:** reproduce the previously failing isolated scenario against the correction, then demonstrate at least 10 consecutive executions of the exact target behavior without recurrence in the normal bounded Playwright environment, followed by the canonical Storybook behavior verification and final automatic `pnpm verify`.
