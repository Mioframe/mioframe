## Goal

Provide one canonical `MDSwitch` Vue adapter over the official Material Switch. Two current product widgets (`SettingsSwitchListItem`, `AppUpdateSettings`) need a non-interactive, decorative track/handle visual that reflects `selected`/`disabled` state inside an `MDListItem` trailing slot, while the list item itself owns the `switch` role, `aria-checked`, and the click-driven action. No product code currently uses Switch as a standalone interactive control. Per the workflow's no-consumer default-scenario rule, architecture additionally selects the unambiguous official standalone default (native click/keyboard toggle, controlled `selected` state) as the one approved library scenario, so the family is not artificially incomplete relative to its official contract.

The simplest viable design is a thin single-host adapter over `m3e-switch` that maps `selected`↔`checked` as a controlled (v-model-style) property, forwards `disabled`, and adds one Mioframe composition extension (`presentation`) that suppresses the renderer's native interactivity for the confirmed decorative scenario without recreating any renderer-owned geometry or motion. No adapter framework, icon slot, drag-to-toggle reimplementation, or component-specific token file is required.

Design basis: [Identity and purpose](./DESIGN.md#identity-and-purpose), [Anatomy and content](./DESIGN.md#anatomy-and-content), [Variants and configurations](./DESIGN.md#variants-and-configurations), [States and behavior](./DESIGN.md#states-and-behavior), [Usage guidance](./DESIGN.md#usage-guidance), and [Accessibility](./DESIGN.md#accessibility).

## Non-goals

- Do not expose the optional handle icon (`selected`/`unselected`/`both` icon configurations). No current consumer requires them; only Storybook-only legacy demo stories exercised icons, which is proof infrastructure, not product demand. See [Anatomy and content](./DESIGN.md#anatomy-and-content) and [Variants and configurations](./DESIGN.md#variants-and-configurations).
- Do not implement drag-to-toggle. It is one of several officially equivalent toggle interactions (tap, click, drag release, keyboard), the installed renderer does not implement it, and recreating pointer-drag gesture geometry in the wrapper would duplicate renderer-owned transient interaction geometry. See [States and behavior](./DESIGN.md#states-and-behavior) and [Source conflicts and unknowns](./DESIGN.md#source-conflicts-and-unknowns).
- Do not expose native form participation (`name`, `value`, form reset/submit behavior). No current scenario places Switch inside a submitted form.
- Do not expose an internal visible-label prop. Official guidance places label text adjacent to, never inside, the switch; the accessible name comes from a consumer-supplied `aria-label`/`aria-labelledby` or a wrapping/associated native `<label>`, never from a Switch-owned label anatomy. See [Anatomy and content](./DESIGN.md#anatomy-and-content) and [Accessibility](./DESIGN.md#accessibility).
- Do not recreate renderer-owned private DOM, focus ring, state layer, ripple-equivalent hover/press shape morphing, elevation, or motion.
- Do not expose all official Switch tokens as public Mioframe tokens. No current or contextual consumer overrides any Switch color, geometry, or state value; the renderer already resolves correct Material defaults directly from Mioframe's public `--md-sys-color-*`/`--md-sys-shape-*` foundation tokens (confirmed in the installed renderer's core token bundle), so no `--md-comp-switch-*` declaration is selected now.

## Current scenarios

1. **Decorative list-item composition (confirmed).** `SettingsSwitchListItem.vue` (`src/widgets/SettingsSections/SettingsSwitchListItem.vue`) and `AppUpdateSettings.vue` (`src/widgets/AppUpdateSettings/AppUpdateSettings.vue`) each render the legacy `MDSwitch` with `presentation :selected="…" :disabled="…"` inside an `MDListItem`'s `#trailing` slot. The `MDListItem` sets `mode="single-action" role="switch" :aria-checked="…" :aria-disabled="…"` and drives the actual toggle through its own `@action` (click) handler; the switch visual is purely reflective and must not be independently focusable, keyboard-operable, or clickable, and must not carry its own accessible name (the list item already owns the accessible name and role). No icon content is used in either scenario.
2. **No confirmed standalone-interactive product consumer.** No current product code renders Switch as the primary interactive, independently accessible control. Per the workflow's no-consumer default-scenario rule, the unambiguous official standalone default — native click/keyboard toggle with a controlled `selected` result — is selected as the one approved library scenario, exposing only the minimum controllable state required to operate that default. Storybook-only legacy demonstration stories (target-hit area, drag interaction, labelled-by example, icon variants) are proof/demo infrastructure, not confirmed product demand, and do not by themselves justify selecting icons or drag.

Design basis: [Anatomy and content](./DESIGN.md#anatomy-and-content), [Geometry and layout](./DESIGN.md#geometry-and-layout), [States and behavior](./DESIGN.md#states-and-behavior), [Usage guidance](./DESIGN.md#usage-guidance), and [Accessibility](./DESIGN.md#accessibility).

### `presentation` — Mioframe composition extension

`presentation` is not an official Material Switch surface. It remains an exceptional Mioframe extension because two confirmed current product scenarios (item 1 above) require a purely decorative, non-interactive Switch visual composed inside an `MDListItem` that already owns the accessible switch role and the click-driven toggle. Without it, the renderer's native focusability, click-to-toggle, and accessible name would collide with the owning list item's own semantics and produce a duplicate/conflicting accessible control. `presentation` does not add a second source of truth for the selection value: the composing consumer continues to own `selected`/`disabled`, and Switch only renders their current values.

## Dependency closure

Dependency families: `none`.

- Material foundation supplies `--md-sys-color-*`/`--md-sys-shape-*`, which the installed renderer consumes directly for its default Switch coloring and shape (confirmed in `@m3e/web`'s core token bundle); foundation is not an official component-family dependency.
- `@m3e/web/switch` is the exact installed private renderer, not a Material family dependency.
- `MDListItem` (`src/shared/ui/Lists/MDListItem.vue`) is the confirmed decorative-composition consumer for the `presentation` scenario. It is generic shared UI, not an official Material family, so it is a migration-stage consumer, not an architecture dependency.
- No other official Material family (Loading Indicator, Button, or otherwise) is composed by or required by Switch.

The dependency queue and dependency review revisions are both `none`. No dependency cycle exists.

## Ownership

- `switch` owns the public Vue API, `selected`↔`checked` controlled mapping, `disabled` mapping, the `presentation` decorative-suppression mapping, the host-attribute allow-list, private renderer typing, exports, and Switch-owned proof.
- `MDListItem` (a different, non-Material shared-UI family) owns the `switch` ARIA role, `aria-checked`, the accessible name, and the click-driven toggle action for the decorative composition scenario. Switch does not duplicate any of that ownership; it only reflects `selected`/`disabled` visually when `presentation` is set.
- Product features/entities (`AppUpdateSettings`, `SettingsSwitchListItem` callers) own the underlying setting's true value, persistence, and the action that changes it. Switch owns no state beyond the reactive prop it is given.
- Material foundation owns the renderer-independent reference/system tokens the renderer consumes for its default coloring and shape.
- m3e owns private DOM, internal click/keyboard toggle handling, focus ring, state layer, hover/press pressed-shape geometry, elevation, motion, and its own accessibility implementation (labels association, ARIA reflection internals).

## Public Vue API

Canonical export:

```ts
import { MDSwitch } from '@shared/ui/material';
```

Props:

| Prop           | Type      | Required/default | Contract                                                                                                                                                                                                                                                                                                                                         |
| -------------- | --------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `selected`     | `boolean` | default `false`  | Official binary selection state (unselected/off vs. selected/on). Controlled: maps to the renderer's `checked` property; a native toggle re-emits the renderer's resulting value through `update:selected` rather than being owned internally by the renderer. `selected` is the official Material term for this axis, not a legacy-copied name. |
| `disabled`     | `boolean` | default `false`  | Maps to the renderer's `disabled` property, which blocks its internal click-toggle handling. Has no effect when `presentation` is true (already fully non-interactive).                                                                                                                                                                          |
| `presentation` | `boolean` | default `false`  | Mioframe composition extension. When true, renders a purely decorative, non-interactive visual: `tabindex="-1"`, `aria-hidden="true"`, and host `pointer-events: none`, fully suppressing native click/keyboard/focus without touching renderer internals. `selected`/`disabled` still control the rendered visual.                              |

Slots: none. No icon slot is selected (see [Non-goals](#non-goals)).

Emits:

- `update:selected(value: boolean)`: fired when the renderer's own click/keyboard toggle changes its internal `checked` value; carries that resulting value so a consumer can complete a `v-model:selected` controlled binding. Not fired while `presentation` is true (the renderer never receives the interaction that would trigger it).

No `change`, `click`, `input`, or `beforeinput` forward is exposed: no current or default-scenario demand needs a second event carrying the same information as `update:selected`, and Button's precedent of exposing exactly the one meaningful public event is followed here.

Refs, fallthrough, and native mapping:

- The component exposes no methods or custom `defineExpose` contract. A Vue component ref resolves through the single custom-element root; no current scenario needs it, unlike Button's overlay/menu positioning use.
- Only the accepted host-attribute allow-list forwards to the single `m3e-switch` host (see [Host-attribute boundary](#host-attribute-boundary)); there is no unrestricted global-attribute or listener fallthrough.
- `selected` maps to renderer `checked` as a typed Boolean property (not a dashed present/absent attribute); `disabled` maps as a Boolean property; `presentation` is wrapper-owned and never reaches the renderer as a property or attribute.
- The renderer host is the semantic interactive owner for the standalone default. Do not add a nested native input/checkbox or wrapper-owned event synthesis.

Design basis: [Anatomy and content](./DESIGN.md#anatomy-and-content), [Variants and configurations](./DESIGN.md#variants-and-configurations), [States and behavior](./DESIGN.md#states-and-behavior), and [Accessibility](./DESIGN.md#accessibility).

## Host-attribute boundary

`MDSwitch`'s single root is the raw `m3e-switch` custom element with no wrapping element (required so the standalone default remains natively focusable/operable and so the decorative scenario can suppress that same native surface at the host). Per `docs/component-adapter.md`'s "Host-attribute boundary" section and the minimum common allow-list it defines, Vue's default automatic `$attrs`/listener fallthrough is not compatible with the accepted [Public Vue API](#public-vue-api).

Mechanism: `MDSwitch.vue` sets `inheritAttrs: false` and explicitly forwards only the allow-list below onto `m3e-switch`. No `v-bind="$attrs"` spread is used anywhere.

### Allowed forwarded host attributes

| Host attribute    | Forwarding rule                                                         | Reason                                                                                                                                                            |
| ----------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `class`           | forward, merged with the internal `md-switch` class, never replacing it | Common host customization; consumer classes must not drop adapter-owned styling hooks.                                                                            |
| `style`           | forward, merged with internal styles, never replacing them              | Same merge requirement as `class`.                                                                                                                                |
| `id`              | forward as-is                                                           | Common host identity attribute, needed for native `<label for>` association per the official adjacent-label pattern.                                              |
| `title`           | forward as-is                                                           | Common host attribute.                                                                                                                                            |
| `data-*`          | forward as-is (wildcard prefix)                                         | Common host attribute family used for test IDs and non-visual hooks.                                                                                              |
| `aria-label`      | forward as-is                                                           | Required accessible-name source for the standalone default per official adjacent-label guidance (Switch has no internal label prop; see [Non-goals](#non-goals)). |
| `aria-labelledby` | forward as-is                                                           | Same accessible-name requirement, for the labelled-by-adjacent-text pattern.                                                                                      |

No other host attribute or listener is forwarded. This is the complete allow-list; extending it requires confirmed consumer demand and an explicit `ARCHITECTURE.md` update, per `docs/component-adapter.md`.

### Explicitly adapter/renderer-owned — must not be forwarded via `$attrs`

| Attribute/listener                                                              | Owner                                                   | Reason                                                                                                                                                                                            |
| ------------------------------------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `aria-hidden`                                                                   | `presentation` prop                                     | Set only by `presentation`, per [State precedence and restoration](#state-precedence-and-restoration). A forwarded `aria-hidden` could desynchronize from the actual decorative/interactive mode. |
| `aria-checked`                                                                  | renderer (internal ARIA reflection of `checked`)        | The renderer owns its own accessibility implementation for the standalone default; the decorative scenario instead hides the node entirely via `presentation`.                                    |
| `aria-disabled`                                                                 | renderer (internal reflection of `disabled`)            | Native disabled semantics belong to the renderer's own accessibility implementation.                                                                                                              |
| `role`                                                                          | renderer (internal accessibility implementation)        | Native role ownership belongs to the renderer, per `docs/component-adapter.md#accessibility-and-native-behavior`.                                                                                 |
| `tabindex`                                                                      | `presentation` prop / renderer native focusability      | `presentation` sets `tabindex="-1"`; otherwise the renderer's own native focus order applies. An independently forwarded `tabindex` could desynchronize from either.                              |
| `checked`/`aria-checked` as raw dynamic attrs                                   | `selected` prop                                         | `selected` is the sole controlled source of the renderer's `checked` property; a forwarded raw `checked` attribute could desynchronize from the controlled contract.                              |
| `icons`                                                                         | deferred; not exposed                                   | See [Selected and deferred Material surface](#selected-and-deferred-material-surface) — `defer`.                                                                                                  |
| `name`, `value`                                                                 | deferred; not exposed                                   | See [Selected and deferred Material surface](#selected-and-deferred-material-surface) — form participation `defer`.                                                                               |
| arbitrary DOM listeners (`click`, `beforeinput`, `input`, `change`, and others) | adapter (`update:selected` only, derived from `change`) | Only the derived `update:selected` emit is honored; an undeclared listener must not attach to the renderer host.                                                                                  |

### Proof ownership

Component contract tests (`components/switch/MDSwitch.test.ts`) prove: allowed `class`/`style`/`id`/`title`/`data-*`/`aria-label`/`aria-labelledby` reach `m3e-switch`; consumer `class`/`style` merge with (not replace) internal `md-switch` class/styles; `icons`, `name`, `value`, raw `checked`, unknown attributes, and undeclared listeners do not reach or modify the renderer; explicit props (`selected`, `disabled`, `presentation`) map correctly; `update:selected` fires with the renderer's resulting value on a simulated native `change`; `presentation` fully suppresses interactivity at the host (`tabindex="-1"`, `aria-hidden="true"`, `pointer-events: none`).

Browser proof (the lowest faithful Storybook behavior spec) additionally demonstrates that undeclared dynamic inputs cannot change actual rendered custom-element state, and that `presentation` mode is unreachable by pointer or keyboard. This proof inspects the observable rendered result, not private shadow DOM.

Design basis: [Anatomy and content](./DESIGN.md#anatomy-and-content), [Accessibility](./DESIGN.md#accessibility), and `docs/component-adapter.md` "Host-attribute boundary".

## Public token contract

No component-specific `--md-comp-switch-*` token is selected. No current consumer overrides any Switch color, geometry, or state value; both decorative-composition consumers render the plain default track/handle appearance. The installed renderer consumes Mioframe's already-public `--md-sys-color-*` and `--md-sys-shape-*` foundation tokens directly (confirmed by grepping the installed `@m3e/web` core token bundle for `md-sys-color-*` references), so no family-owned mapping file is required for correct default rendering.

Per `docs/component-tokens.md`'s "Selecting a public component token" criteria, a token is added only when a confirmed current scenario requires the rendered part/state (criterion 3) — no such scenario exists today. If a future contextual override scenario is confirmed (for example a Switch composed on an inverse or tinted surface), it requires a new architecture revision and a component-tokens.md-compliant state/part/fallback trace, following the Button Snackbar-token precedent.

No `components/switch/tokens.css` file is created by this architecture.

## State precedence and restoration

- `presentation` has full interaction precedence: when true, the host is unconditionally non-focusable (`tabindex="-1"`), hidden from the accessibility tree (`aria-hidden="true"`), and unreachable by pointer (`pointer-events: none`) — regardless of `disabled` or `selected`. `disabled` has no additional observable effect in this mode.
- When `presentation` is false, `disabled` blocks the renderer's native click-toggle handling and dims the visual per official contract; per [Renderer mapping and gaps](#renderer-mapping-and-gaps), whether it also removes native focusability is confirmed only after browser proof.
- `selected` is the sole controlled source of truth: every reactive update to the `selected` prop sets the renderer's `checked` property. A user-driven native toggle (click, or confirmed keyboard activation) changes the renderer's own internal `checked` value first; the wrapper reads that resulting value from the native `change` event and emits `update:selected` so the owning consumer can update its source of truth and keep the prop synchronized. There is no wrapper-owned duplicate selection state.
- `update:selected` never fires while `presentation` is true, because no interaction can reach the renderer to produce a native `change` event in that mode.
- Mount, prop updates, and `presentation` toggling create no wrapper-owned animation or interaction state; the renderer owns its own state-layer/pressed/hover lifecycle and its own reconnect behavior.

## Risks

- m3e is the Web renderer despite official Web Expressive availability caveats seen on other families; Switch's own DESIGN.md records no "Web Expressive: unavailable" caveat, but browser proof must still validate observable parity for the selected subset.
- The `disabled` tab-reachability and Enter-key activation gaps are genuinely unresolved pending browser evidence; implementation must not assume either result and must not silently paper over a real divergence with an undocumented workaround.
- The renderer's internal optimistic `checked` toggle on click means a controlled `selected` binding that lags (e.g., an async consumer update) could visually desynchronize for one frame; implementation must verify this against the accepted native-`<input>`-v-model-equivalent pattern.
- `presentation`'s `pointer-events: none` suppression must be verified under both mouse and touch input; a renderer update could change internal event delegation in a way that requires revisiting the suppression mechanism.
- Removing the legacy `src/shared/ui/Switch` component also removes its custom drag-to-toggle and icon-slot capabilities; migration must confirm neither current consumer or any undiscovered consumer relies on them before deletion.

## Forbidden

- Expose renderer variants/types/tags/attributes/events/CSS variables (`icons`, `name`, `value`, raw `checked`, `--m3e-switch-*`), or add renderer capability for symmetry.
- Add icon slots, drag-to-toggle, form participation, or an internal label prop without a revised architecture and confirmed demand.
- Recreate renderer-owned drag gesture geometry, pressed-shape morphing, state layer, focus ring, or motion in the wrapper.
- Let `presentation` leave the element focusable, keyboard-operable, or reachable by pointer under any input modality.
- Publish a `--md-comp-switch-*` token without a confirmed contextual consumer, or derive a public token name from `--m3e-switch-*` renderer vocabulary.
- Treat unit tests, stories, host custom properties, snapshots, green verification, or implementation evidence as substitutes for rendered-anatomy proof or as proof of subjective visual/motion quality.
- Use unrestricted `v-bind="$attrs"` fallthrough, omit `inheritAttrs: false` on the single `m3e-switch` root, or forward any attribute or listener outside the accepted [Host-attribute boundary](#host-attribute-boundary) allow-list.
- Introduce a generic wrapper, adapter base class, registry, schema, directive, or composable framework to implement host-attribute filtering or the `presentation` suppression; keep it local to `MDSwitch.vue`, per `src/shared/ui/material/AGENTS.md`.
- Preserve a compatibility alias for the removed legacy `src/shared/ui/Switch` component during or after migration.
