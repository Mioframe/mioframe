# Extended FAB architecture

Status: ready
DESIGN.md reference: `src/shared/ui/material/components/extendedFab/DESIGN.md`
Renderer revision: @m3e/web@2.7.4
Revision summary: Initial architecture. Selects the small, primary-container Extended FAB (icon + label) as the confirmed scenario migrating `RepoExplorerPane`'s legacy `MDExtendedFab` usage, composing the same `m3e-fab[extended]` renderer element already validated `direct` by the sibling `floatingActionButton` family.
Remaining blockers: none
Required return family: none
Required return stage: none
Implementation readiness: ready
Dependency families: none
Dependency queue: none

## Goal

Provide `MDExtendedFab` as the canonical Extended FAB, configured exactly as `RepoExplorerPane`'s confirmed product scenario requires: small size, Primary-container color, a required accessible/visible text label, an optional decorative icon, and normal native activation. Small is selected because it is the officially recommended baseline replacement (DESIGN.md's "no longer recommended" baseline note) and is also `RepoExplorerPane`'s current effective configuration; Primary-container is selected because it is both the documented Material default color mapping and `RepoExplorerPane`'s current effective configuration. The component composes the same `m3e-fab` custom element the `floatingActionButton` family already owns independently, using its documented `extended` attribute and `label` slot rather than a new renderer artifact.

## Non-goals

- Product placement, scroll persistence, action availability, tooltip composition, routing, loading/busy presentation, or action state.
- Plain FAB, FAB menu, multiple actions, or container-transform/scroll-collapse motion between FAB and Extended FAB.
- Medium/large size, non-Primary-container color (including the officially "not recommended" surface style and the narrative-undocumented branded style), lowered elevation, disabled, link, form, or public token configuration.
- A canonical icon family, raw renderer icon element, generic size/color prop API, generic adapter framework, or renderer workaround.
- Owning or modifying `floatingActionButton`, `FabContainer`, or any other family/module.

## Current scenarios

`RepoExplorerPane.vue` (`src/pages/RepoExplorer/RepoExplorerPane.vue:194-196`) renders the legacy `MDExtendedFab` inside the legacy `FabContainer`:

```vue
<FabContainer v-if="canEditDirectoryContents !== false" auto-hide>
  <MDExtendedFab label="Add" md-symbol="add" @click="onClickAdd" />
</FabContainer>
```

The legacy component's effective configuration is its own defaults: `size="small"`, `color="primary-container"`, no `tooltip`, no `loading`. This is the confirmed product scenario: an "Add" action FAB with a visible/accessible "Add" label and a decorative icon (currently a `MDSymbol` ligature glyph; DESIGN.md's confirmed Extended FAB icon contract — mirroring `floatingActionButton`'s established `direct` composition evidence for the identical renderer default slot — requires one decorative inline filled SVG, not a ligature icon font; the legacy `md-symbol="add"` value is a legacy-only capability that migration must translate to an equivalent inline SVG, not a canonical public surface).

`FabContainer` (placement, auto-hide-on-scroll, floating positioning) is a separate, already-generic shared-UI module (`src/shared/ui/Button/FabContainer.vue`) outside Material ownership; this architecture does not change it. Its single documented slot ("A single `MDFab` or `MDExtendedFab` action…") remains satisfied by the canonical `MDExtendedFab` once migrated.

No other current `src/pages`, `src/widgets`, `src/features`, or `src/entities` file imports `MDExtendedFab` or `FabContainer` (confirmed by repository-wide search).

When the "Add" action is unavailable, `RepoExplorerPane` already omits the entire `FabContainer` (`v-if="canEditDirectoryContents !== false"`) rather than rendering a disabled FAB; canonical `MDExtendedFab` therefore needs no disabled surface, matching official DESIGN.md's undocumented Disabled state for Extended FAB and matching `floatingActionButton`'s identical decision.

An empty or non-conforming icon slot is invalid caller input, mirroring `floatingActionButton`: in development the adapter warns for present-but-non-SVG icon content; it does not synthesize a glyph or fall back to another component. Because DESIGN.md's official anatomy documents the icon as optional (unlike the plain FAB, where it is mandatory), and because the confirmed scenario always supplies one, the icon slot is implemented as optional content: omitting it renders label-only, and content that fails the SVG contract is a development-time warning, not a silent transform.

## Dependency closure

Dependency families: none. `extendedFab` independently imports `@m3e/web/fab` and types against `M3eFabElement`/`FabSize`/`FabVariant`, the same public renderer package the already-complete `floatingActionButton` family imports. This is not a Mioframe dependency relationship in the `docs/component-adapter.md` sense (no composition through `floatingActionButton`'s public `MDFab` API, no shared Vue component, no shared token namespace — `floatingActionButton` owns no `--md-comp-fab-*` public tokens either): both families are independent official Material components (confirmed distinct routes/slugs in DESIGN.md's source ledger) that happen to be implemented by the same upstream custom element, exactly as Material treats FAB and Extended FAB as related-but-separate components. Each family keeps its renderer typing, private mapping, host-attribute filtering, and proof entirely local, per `docs/component-adapter.md`'s "keep mappings owner-local" rule. There is no dependency cycle: the active path is `extendedFab` only.

The selected icon is a caller-owned inline SVG, not a Material component dependency, mirroring `floatingActionButton`'s identical decision and identical installed-artifact evidence (`::slotted(svg:not([slot])) { width: 1em; height: 1em; }` on the shared `M3eFabElement` shadow stylesheet).

The foundation remains the existing owner of system color, elevation, shape, focus, and theme-mode values; it is established shared infrastructure, not a family dependency or queue entry.

## Public Vue API

`MDExtendedFab` exposes exactly:

| Surface         | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `label: string` | Required. The visible label text and the accessible name. Rendered as light-DOM text content projected into the renderer's `label` slot, and explicitly mirrored to the host `aria-label` (the same explicit-binding pattern `floatingActionButton` already established and browser-proved, chosen over relying on unverified renderer shadow-tree content-based accessible-name aggregation).                                                                                                                                                                                                                                                                                   |
| `#icon` slot    | Optional. When present, renders exactly one direct inline `<svg>` root with a `viewBox`, no `slot` attribute, decorative accessibility (`aria-hidden="true"` and no focusable/interactable descendant), and paint based on `currentColor` — identical contract to `floatingActionButton`'s `#icon` slot, including the filled-not-outlined Material-compatible artwork requirement from DESIGN.md's "Anatomy and content" guidance. The SVG may be supplied inline or by a Vue helper whose rendered root is that SVG. Text nodes, wrappers, renderer custom elements, images, and additional visible labels are unsupported. When omitted, the Extended FAB renders label-only. |
| `@click`        | Forwards the native `MouseEvent` unchanged after ordinary renderer activation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Host attributes | Only `class`, `style`, `id`, `title`, and `data-*` are forwarded. `class`/`style` merge with the family-owned host values. They are generic HTML forwarding, not a supported Material size, color, or renderer-token API.                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

The single raw renderer host uses `inheritAttrs: false`. It pins private `small`, `primary-container`, and `extended` (always present/true) values and rejects every other fallthrough attribute and listener, including `aria-label` (owned explicitly by the adapter from `label`), `disabled`/`disabled-interactive`, `lowered`, `size`, `variant`, link/form attributes, and arbitrary renderer inputs. There is no default (unnamed) slot exposed to consumers, no additional emit, no `v-model`, and no component-ref/expose contract.

## Implementation passes

1. Create `MDExtendedFab.vue` as one `m3e-fab` host with package-derived private typing (`FabSize`, `FabVariant`, `M3eFabElement` from `@m3e/web/fab`), explicit `small`/`primary-container`/`extended` constants, `inheritAttrs: false`, explicit `label`/`click`, and local host-attribute allow-list filtering — following the same structure as `floatingActionButton/MDFab.vue` (see that file for the established allow-list/typing pattern), adapted for the label slot and the optional (not required) icon slot.
2. Bind `label` to both the renderer's named `label` slot (as light-DOM text) and the host `aria-label`.
3. Keep the icon slot projected directly to the renderer's default (unnamed) slot, `v-if` its presence rather than requiring it. Add development-only validation that warns when icon slot content is present but is not exactly one direct SVG root (mirroring `floatingActionButton`'s DEV check), and does not warn when the slot is empty. Document (as a caller-contract requirement, not a runtime-validated property) that supplied artwork must be filled, Material-compatible iconography, matching `floatingActionButton`'s identical documented requirement.
4. Do not render `m3e-icon`, create an `MDIcon`/`MDSymbol` dependency, wrap the SVG or label text, set a renderer CSS variable publicly, or inspect shadow DOM.
5. Author `MDExtendedFab.test.ts` proving: required `label` prop renders as visible text and `aria-label`, optional icon slot renders when present and is absent when omitted, DEV warning for non-SVG icon content, click forwarding, fixed private `size`/`variant`/`extended` values, and host allow-list/rejection coverage (mirroring `MDFab.test.ts`'s established coverage shape).
6. Author `MDExtendedFab.browser.spec.ts` owner-local: prove accessible role/name ("Add"-style fixture), native click, Enter/Space activation, rejected dynamic fallthrough, and public numeric geometry — a 56px container height, 24px icon box, 16px leading/trailing padding, and 8px icon-label gap at the configured 1:1 CSS-pixel environment — for the icon+label fixture. Do not query private renderer parts.
7. Author `MDExtendedFab.visual.spec.ts` owner-local: screenshot only the filled-SVG-and-label-backed resting, hover, focus, and pressed appearance, plus the label-only (no-icon) appearance for visual completeness (visual proof may cover this even though it carries no separate numeric geometry claim). No keyboard, geometry, or computed-style success criteria in this file.
8. Author `MDExtendedFab.stories.ts` with a `Default` story (icon + "Add"-style label) and any additional fixtures the browser/visual specs need (e.g., a label-only variant, host-attribute-boundary variant), following the established `MDFab.stories.ts` fixture-per-contract convention. Update `docs/roadmap.md` is out of scope for this stage.
9. Export `MDExtendedFab` from the family `index.ts` and the root `@shared/ui/material` barrel, mirroring `floatingActionButton`'s export shape.
10. Keep tokens private/default-backed. If exact-version inspection or browser proof finds a real selected-default divergence (geometry, color, or focus-indicator source-conflict resolving incorrectly), stop implementation, add the required `M3E-*` record, and return to architecture rather than adding an unrecorded workaround.

## Acceptance criteria

- `MDExtendedFab` exposes only `label`, the optional constrained `icon` slot, `click`, and the explicit generic host allow-list.
- The fixed default cannot be changed to disabled, medium/large size, another color, lowered, link/form, or another anatomy through public props or rejected attributes/listeners; generic `class`/`style` forwarding remains unsupported as a Material customization API.
- Every selected story and proof fixture uses one decorative direct SVG with filled Material-compatible artwork when an icon is shown, never bare text, a ligature/font glyph, outlined/stroke-only artwork, or a renderer element.
- The browser proves the icon+label default is a 56px-tall container with a 24px icon, 16px leading/trailing padding, and an 8px icon-label gap, alongside accessible native activation and a computed accessible name equal to `label`.
- Visual proof covers the resulting default appearance (icon+label and label-only) and renderer-owned transient feedback without replacing browser contracts.
- No public Extended FAB component token, renderer workaround, or dependency is introduced.
- `RepoExplorerPane` is migrated to canonical `MDExtendedFab` with the "Add" action preserved at its current entry point and interaction tier, and legacy `MDExtendedFab` is fully removed with no compatibility alias.

## Risks

- DESIGN.md documents no official minimum-width or leading-space value for the label-only (no-icon) small/medium/large configurations (only the baseline configuration has an explicit padding attribute). The icon-omitted rendering path is implemented (matching official optional-icon anatomy) but carries no numeric geometry proof obligation beyond what the renderer naturally produces; a future confirmed label-only scenario should revisit this gap rather than assume current visual proof resolves it.
- DESIGN.md documents no distinct focus-indicator token for the Primary-container (tonal-container) color set at any size. The renderer's shared, non-variant-scoped `m3e-focus-ring` default is accepted without an exact official token trace; this remains a `source-conflict` recorded here, not silently treated as `direct`.
- A future `@m3e/web` revision must revalidate the direct-SVG icon sizing/color handoff, the small-size geometry constants, and the `extended`/`label`-slot composition before retaining the `direct` classification.
- If `RepoExplorerPane`'s confirmed "Add" scenario ever needs a second size/color combination, a fresh architecture pass is required rather than widening this adapter's fixed constants ad hoc.

## Forbidden

- Bare text, a ligature/font-icon glyph (`MDSymbol`/`md-symbol`), wrapped content, images, outlined/stroke-only artwork, a raw `m3e-icon`, or a second visible label in the selected icon slot.
- Disabled, disabled-interactive, medium/large size, non-Primary-container color (including surface and branded), lowered, link, form, tooltip, loading/busy, or FAB-menu/scroll-transform API expansion without a fresh architecture.
- Renderer-private attributes, events, types, CSS variables, shadow DOM, state copies, timing repairs, descendant cascades, or `!important` outside the family.
- A public token, compatibility alias, icon framework, generic adapter framework, or additional product consumer invented for completeness.
- Composing `floatingActionButton`'s public `MDFab` component, importing its private files, or otherwise treating it as a dependency of this family.
- Browser assertions in visual specs, screenshots in browser specs, or treating either as a substitute for the other.
- New runtime SVG-shape/semantic validation (for example, detecting filled versus outlined artwork) added to DEV validation or tests; filled-icon artwork remains a caller-contract and canonical-fixture requirement, matching `floatingActionButton`'s identical restriction.
